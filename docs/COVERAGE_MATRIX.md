# 亚太网络安全监管覆盖矩阵

定位与优先级更新：2026-10-29。当前数据的文件、条款及实体清单由[覆盖明细](coverage-inventory.md)自动生成；本页维护目标范围、覆盖判断与缺口。

## 项目定位

**面向跨国企业常见亚太经营地域的开源、离线网络安全监管要求映射与差距评估工具，以中国香港和新加坡为发展重点。**

核心用户是跨国企业的区域网络安全、科技风险、合规、法务及内审团队，包括区域总部、当地子公司和共享服务中心。
先建立一般企业能够使用的跨行业基线，再按金融牌照、关键基础设施指定及其他受监管业务叠加专项要求。
已有金融业资料继续保留，但不能代表一般企业的地域覆盖已经完整。地域优先级是产品决定，不代表监管义务的轻重。

### 地域与发展顺序

| --- | --- | --- | --- |

不追求按国家数量扩张。新增地域应有明确使用场景、官方来源和维护责任，并采用相同的覆盖口径。

## 阅读口径

矩阵按 **地域 → 适用对象 → 文件／主题 → 条款 → 缺口** 组织。每个主题的“已收录条款”在自动明细中可以追溯到控制 ID、实体与业务特征。

| 状态 | 含义 |
| --- | --- |
| 部分覆盖 | 已有相关控制，但仍有未拆解条款、概括引用、适用性或来源定位缺口；不能称为完整 |
| 未覆盖 | 尚无该文件／主题的可用控制；只有相关上位法、其他监管机构的规则或类似控制不算覆盖 |
| 待核验 | 有线索或登记来源，但尚未建立明确的文件、适用条款与控制对应关系 |
| 参考 | 背景文件、FAQ、模板或索引；不能按“已覆盖文件”计数 |
| 完成所声明范围 | 仅在明确列出范围内全部适用条款，逐项映射或说明排除原因，并复核原文、适用性与版本后使用 |

**本轮没有把任何地域或整份文件认定为完整。** 当前尚无经过逐条复核的应覆盖条款分母，因此不计算地域覆盖百分比。
控制数量、原文／节录数量及链接可达性都不是法律完整性证明。`summary` 是概括说明，不能当作逐字原文；一项控制也可能概括整章。

下表的 P0／P1／P2 是本次覆盖工作的顺序，与历史开发计划中的功能阶段、控制的 `baseline`／`enhanced` 均无对应关系。

## 本轮可执行顺序

1. **P0：香港、新加坡的一般企业基线。** 香港补精确出处和跨境／委托处理；新加坡补一般企业入口、PDPA 保安／事件／跨境及条件性 CSA 适用性。新增条款必须进入运行时数据、英文层及繁体生成物，不能只在矩阵改成“覆盖”。
2. **P1：重点地域的专项深度与差额。** 先处理目标企业实际涉及的行业；细化香港章节级控制、新加坡 TRM／外包／BCM，补香港—新加坡的事件通知、委托处理、访问控制、测试及韧性差额。
3. **P2：其他已登记地域。** 保持来源和已有数据可用，优先补会影响目标企业实际经营／数据流的义务。候选地域在明确需求后再排期。

两地一般企业基线验收时，分别用区域总部、共享服务中心、云端／委托处理，以及已指定关键基础设施等情景核对适用性。
当前新加坡、澳大利亚、马来西亚不能仅靠现有金融实体选项完成一般企业的范围判断；这一点本轮只登记为缺口，尚未实施。

## 如何维护及认定完成

- 自动明细来自当前仓库的运行时数据，运行 `node tools/coverage-matrix.mjs` 更新；CI 使用 `--check` 检查是否同步。
- 改动来源、控制、实体或业务特征后，先更新自动明细，再修改本页相应覆盖状态及缺口。仅新增来源链接时保持“待核验／参考”，不能标为覆盖。
- 每个文件范围应列出全部候选条款；逐条记录“映射的控制 ID／排除理由／待处理”。必须明确评估的是整份文件还是指定章节及业务场景。
- “完成所声明范围”需要原文／节录及精确定位、实体与业务触发条件、法例／通知／指引的法律地位、版本及生效／过渡日期、人工复核日期与复核记录。不能仅凭自动校验认定完成。
- `verifiedOn` 是既有出处的实际核验日期；本次研究或重生成明细不自动推进它。本矩阵中的新增官方链接用于识别缺口，尚不等于已逐条核验或纳入应用。
- 非现行提案、咨询及观察事项应另列为观察项，不能混入现行义务。法律义务强度与产品开发优先级始终分别维护。

本轮交付是范围与覆盖矩阵，附当前代码的逐条盘点；没有新增法规控制或改变用户已有评估记录。
